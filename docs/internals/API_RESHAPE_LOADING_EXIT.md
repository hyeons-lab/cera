## Work that follows the loading design gate

- P1 installs additive public types and generates actual production bindings.
  Compare old/new surfaces and compile existing callers, including the four
  native async constructors (path, bytes, parts and bundle). Keep them supported
  while defining any new asynchronous builder's consumption and cancellation.
  A synchronous candidate does not authorize removal or blocking replacement of
  existing asynchronous entry points.
- P1/P2 target and release checks still include advertised browser/device paths,
  Linux invalid-path regression execution, remote catalog/explicit manifests,
  broader conversion/CDN behavior, concurrent device use and measured load/network
  costs. If an additive implementation changes these paths, its regression check
  becomes a prerequisite to shipping that change; this audit does not waive it.
- Chat prototypes, recovery, turn phases, templates, warm-KV budgets and first-party
  chat migration remain in P0.1/P0.2/R0/R1/P1/P2. Loading consumes or shares model
  ownership; it must not introduce replay or reconstruction of a live Session.
- Leap artifact profiles, conversation history/streams, LoRA/embeddings and
  package replacement applications remain C0/C1/C2. Whisper/VAD/hotword unified
  loading remains F5; standalone APIs stay supported.

foreign DownloadProgressSink. It covers explicit HF quant/revision selection,
